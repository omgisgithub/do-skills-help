## Common design (same as the 31 Oct experiment, `SPEC.md`)

- Tasks t1–t9 (`tasks/`), conditions from `conditions/` (C0 nothing, C1 own `spec-check` skill,
  C4 bloated 730-line context file, C5 50 public skills). Unchanged.
- Fresh `/tmp` workspace per run (`runner.build_ws`), hidden grading after the run on a copy
  (`harness/grade.sh` via `runner.grade`). Pass = all hidden tests pass. Timeout 900 s.
- Prompt (all X1/X2 runs and X3 "plain"): "Read TASK.md in the current directory and complete the
  task it describes. Work only inside the current directory. Do not ask questions; when you are done, stop."
- X3 "named" prompt = the same text + " Use the spec-check skill if it fits."
- Driver: `harness/runner_x.py` (new). It imports `runner.py` and `backends.py` unchanged.
  Order: rep-major, then task, then condition. Max 3 concurrent runs per model.
- Launch order X3 → X1 → X2 → X4. The three providers have separate budgets, so X3, X1 and X2 run
  side by side (started in that order); X4 starts after X1 (same Plus meter).
- Output: `runs_x/<run_id>/` (stream, stderr, workspace, grade, Codex rollout) and `runs_x/results.jsonl`.
- Skill opened = a `Skill`/`skill` tool call naming it, or any tool input containing
  `skills/<name>/` (the `skilluse.py` rule). "Opened mine" = the C1 skill `spec-check`.
- Analysis: `analyze_x.py` → `RESULTS_X.md`. Infra errors (no tool call + error, or a limit hit)
  are excluded; the last valid attempt per (model, arm, task, rep) counts. Timed-out runs are graded as usual.
